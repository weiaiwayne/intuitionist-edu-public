# Public release scope

This repository is maintained separately from the private development workspace. The release rule is inclusion by explicit selection, not publication of a filtered mirror.

## Included in the first release

Newly written framework documentation, a conceptual diagram, technology descriptions, evaluation questions, citation metadata, licensing notices and a small release-package checker.

## Excluded

- Agent memories, personal preferences, private profiles and live system instructions.
- Conversations, email, operational logs, job records and internal reviews.
- Student information, private course records and institutional material without release permission.
- Credentials, server settings, deployment files and private service identifiers.
- Unpublished proposals, abstracts, research results, codebooks and study materials.
- Datasets, collected content, third-party manuscripts and model checkpoints.
- The private repository's Git history, branches, issues and attachments.

## Future additions

Each proposed addition needs its own rights and privacy review, an accurate status label and a reproducibility statement. Prior publication, online availability or absence of passwords does not by itself establish permission to redistribute.

Keep the public and private repositories separate. A new public release should identify exactly which files are intended to be shared. Do not use a whole-repository copy or force-push private history into this repository.

The included checker helps detect unexpected files and obvious sensitive patterns. It is a supporting check, not a guarantee of confidentiality or rights clearance.
