# Workflow

A useful task brief makes four things explicit: the task, what is in scope, the intended use and the completion condition.

## Define before dispatch

Name the participants and their responsibilities. Decide whether work should be solo, collaborative or independent. If judgments must be compared independently, define access boundaries before anyone reads a peer's output.

Specify the consequence of a failed check. Some tasks can proceed with a recorded limitation; others need a changed method or a stop. A generic task status cannot replace that decision.

## Produce inspectable work

Keep the brief, inputs, method and output references together. Claims about a running job should come from current execution records, not an agent's recollection. Success status means the process completed; scientific correctness requires separate checks.

## Review methods and interpretation

A review should inspect whether the method answers the question, whether the analysis unit matches the data structure, and whether the written conclusion follows from the results. Matching a published count or producing a plausible table is not enough.

Keep method reconstruction, implementation repair, methodological revision and exploratory sensitivity distinct. They answer different questions.

## Correct visibly

Preserve the previous result and identify what supersedes it. Explain the reason for a correction and which downstream artifacts depend on it. A repaired upstream label or feature may require checking training, validation, sampling and evaluation, not only the test labels.

## Close with a decision

The human decides what to accept, defer, revise or release. The record should distinguish a completed task from a fully validated claim. Unresolved issues should remain visible with an owner or a stated limitation.

## Retain selectively

A reusable lesson should identify the situation in which it applies, the action or judgment it changes, its evidence and its limits. Repeated rules and untested generalizations can make future context less useful. See [memory and learning](memory-and-learning.md).
